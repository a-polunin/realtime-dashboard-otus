# SLO/SLI по узлам системы

Беру три узла с [диаграммы сервисов](07-services-diagram.md), которые уже засветились в [дереве полезности](02-utility-tree.md) и [матрице рисков](12-risk-matrix.md), и превращаю их меры из сценариев в SLI/SLO — то есть не разовую проверку конкретного кейса, а обещание на скользящем окне, по которому можно алертить.

## DELIV (доставка клиентам)

**SLI:** доля событий, для которых время от "ушло из STATE" до "отрисовано у клиента" не превышает 2с (p95), по логам доставки за 28 дней.

**SLO:** 95% событий укладываются в 2с — тот же порог, что в S3, но на всё окно, включая пиковые матчи.

## ARB (выбор и валидация источников)

**SLI:** доля времени без пометки _устаревшие_, за 30 дней.

**SLO:** 99% времени без пометки _устаревшие_ — агрегат меры из S1 (переключение на резерв за 45с), чтобы такие сбои не накапливались за месяц.

## Фронтенд: доставка бандла с CDN

**SLI:** TTFB бандла с CDN, p95, по RUM за 7 дней.

**SLO:** p95 TTFB — десятки мс, без деградации на старте матча
